# 项目上下文

## 一句话目标

构建一个以 Go 为主语言、以 OpenTelemetry 为遥测标准、以 SLO 和故障闭环为可靠性核心，并逐步演化为平台工程与 AI 可观测性实践的项目。

## 当前范围

- M0 工程基线已经完成终局审计；当前处于进入 M1 前的施工包准备点，M1 业务源码尚未开始。
- 近期可投递目标是 M1–M3；M4–M8 是后续演化路线，不是当前阻塞项。
- 首先做模块化单体；不为制造“微服务感”提前拆分服务。
- 当前主仓库：`github.com/9Alimay/lyapus`。

## 长期不变的工程原则

- 先形成可运行、可测试、可解释的最小版本，再增加深度。
- 每项技术结论必须有测试、实验或可复现步骤支持。
- 文档描述已实现事实；远期想法放入阶段计划或 backlog，不画成当前架构。
- 真实密钥、IP、账单、代理端口与未脱敏遥测永不进入 Git。
- 对外契约优先稳定、显式、可版本化；内部实现可以重构。

## 术语

- 阶段：方案书中的 M0–M8。
- 施工包：某阶段的 `plan.md`、`contracts.md`、`checklist.md`、`outcome.md`。
- 契约：调用方可依赖的 API、数据结构、错误语义或配置格式。
- 证据：能复现某项结论的测试、命令输出、报告、演示或 Git tag。
