# 知识笔记地图

知识笔记的作用不是收集资料，而是把“原理 → 工程选择 → 最小实验 → 面试表达”压缩成可复习的卡片。

## 使用规则

- 一个主题一份笔记，标题描述问题而不是工具名堆砌。
- 优先写自己能解释或已在项目中验证的内容；外部资料只链接和总结，不大段复制。
- 每份笔记使用 `../templates/knowledge-note.md` 的骨架。
- 新知识进入对应主题目录；跨主题术语进入 `glossary.md`。
- 当笔记指导了项目决策时，在笔记中链接 ADR 或阶段施工包。

## 学习地图

| 目录 | 重点问题 | 主要阶段 |
| --- | --- | --- |
| `go/` | 如何写正确、可测、可诊断的 Go 服务？ | M0–M8 |
| `linux/` | 进程、内存、文件、网络如何共同表现故障？ | M0–M7 |
| `data/` | SQL、索引、事务、缓存和消息如何保证数据语义？ | M1–M3 |
| `distributed-systems/` | 超时、重试、幂等、背压和一致性如何处理？ | M2–M6 |
| `cloud-native/` | 容器、Kubernetes、Helm、控制器如何交付能力？ | M1、M5–M6 |
| `observability/` | 指标、日志、追踪如何关联并解释故障？ | M3–M8 |
| `reliability/` | SLO、告警、事件、处置和复盘如何形成闭环？ | M4–M8 |
| `ai-observability/` | 如何评测 AI 诊断并限制自动化风险？ | M8 |

## 建议的单份笔记长度

优先控制在 1–3 个屏幕。主题过大时按问题拆分，例如把“Kafka”拆成“分区与顺序”“消费组与重平衡”“至少一次与幂等”。
