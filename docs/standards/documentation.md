# 文档规范

- Markdown 是正式文档真源；使用 UTF-8、LF 换行。
- 文档中的代码片段只用于解释关键约束；完整可执行代码以仓库源码和 Git commit 为准。
- 在协作式手敲教学期间，`docs/progress/handoffs/` 可暂存一个短小、完整且可独立落地的代码块，作为断联恢复用的“接力稿”。每份接力稿必须标明目标源码路径、创建原因和删除条件；确认同一内容已写入源码并通过约定验证后立即删除。它不是长期代码副本，也不能替代 Git commit。
- 每份阶段文档必须写清“已完成”“未完成”“不做什么”，避免把计划描述成事实。
- 对会影响接口、依赖、存储、部署或安全边界的建议，必须同时写明问题、选择理由、替代方案、适用边界和验证方式；不能只给结论。
- 每个可量化结论必须包含环境、命令、参数、结果和限制。
- 不提交密码、token、私有 IP、精确账单、真实代理端口或未脱敏日志。
