# HTTP API 规范

- 从第一版开始使用 `/v1` 前缀。
- 成功响应返回业务资源或明确的空响应；不混用多种包装格式。
- 错误响应统一为：`code`、`message`、`request_id`；`code` 是稳定、可供程序判断的 snake_case 字符串。
- 创建资源使用 `POST`，查询使用 `GET`，完整更新使用 `PUT`，部分更新使用 `PATCH`，删除使用 `DELETE`。
- 列表接口从简单、稳定的 `limit` 和游标开始；在需要前不提前设计复杂筛选语言。
- 所有可能重试的写操作在引入幂等需求时明确 idempotency key 的语义，不能隐式假设重试安全。
