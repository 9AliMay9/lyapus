# ADR-0003：PostgreSQL 作为项目主库

- 状态：accepted
- 日期：2026-07-27

## 背景

M1 将进入 Service Catalog、关系模型、约束、迁移、事务、索引和并发正确性实践。项目需要一个能支撑这些学习目标、生态成熟且后续阶段仍可复用的关系数据库。

ADR-0001 已经接受“从模块化单体开始”的决策。为遵守“已接受 ADR 不原地重写”的规则，数据库决策单独记录在本 ADR；这不表示 PostgreSQL 已在 M0 实现。

## 决策

从 M1 开始使用 PostgreSQL 作为项目主关系数据库。业务约束优先通过清晰的数据模型、数据库约束、事务和可验证迁移表达；在出现真实需求前不引入多主库或多种关系数据库。

## 后果

- M1 需要锁定 PostgreSQL 版本、迁移工具、连接方式和测试隔离策略。
- repository 层必须保留清晰业务边界，但不为虚构的数据库替换需求建立复杂抽象。
- M2–M4 可继续复用同一业务数据真源，并围绕事务、消息、故障和可观测性形成连续证据。
- PostgreSQL 的选择不等于已经证明生产容量、高可用或故障转移能力。

## 备选方案

- SQLite：适合嵌入式和极简本地场景，但不足以覆盖本项目希望练习的服务端并发、运维与 PostgreSQL 生态。
- MySQL：同样是成熟关系数据库，但项目路线、目标练习和后续工具链已经围绕 PostgreSQL 收敛；并行维护两种数据库没有收益。
- 从 M1 开始使用多种存储：拒绝。会稀释 SQL、事务和索引这一阶段的主难点。
