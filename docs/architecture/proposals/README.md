# 架构提案

在尚未决定、但会影响接口、存储、部署、成本、安全或后续阶段的技术问题上，才写一份提案。它记录思考过程，不要求马上得出结论；普通实现任务不需要建立提案。

命名：`P-0001-short-title.md`。

提案进入决策时：

1. 补齐可验证的事实、实验或上游文档依据。
2. 在提案中写明推荐方案和不选其他方案的原因。
3. 新建 ADR，并在两份文档互相链接。
4. 将实施任务写入当前阶段施工包；实施完成后链接 benchmark、runbook 或 postmortem 证据。

临时、低影响的想法可先写入当前阶段 `plan.md` 的“待确认事项”；一旦影响公共接口或成本/安全边界，就升级为提案。
